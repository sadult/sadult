## About

I build **shipped desktop and terminal software** — network clients, automation tooling and AI interfaces — with a bias toward things that run on a real machine, survive a bad connection, and look good while doing it.

My work clusters into three lines:

- **The Berry family** — a shared design system and codebase philosophy across `Mulberry`, `Dewberry`, `Elderberry` and `Huckleberry`.
- **Low-level networking** — TLS record engineering, SNI spoofing, packet injection through WinDivert, TUN adapters and routing.
- **Systems that live where people already are** — Telegram bots, browser extensions, terminal UIs.
- **Autonomous agents** — `HOMA` plans, calls real tools and drives a real browser on hardware you own, never in someone else’s cloud.
- **Privacy-first messaging** — `AnonChat` relays anonymous group chat through Telegram with a schema that physically cannot store a message.

<summary><b>Shade Engine — packet-level SNI spoofing</b></summary>
<br/>

> A Windows SNI-spoof client with a **built-in packet-injection engine**, decoupling three values that are normally welded together.

| Layer | Controlled by |
| :--- | :--- |
| Local entry point | `LISTEN_HOST` + `LISTEN_PORT` |
| Advertised TLS hostname | `FAKE_SNI` |
| Real network destination | `CONNECT_IP` + `CONNECT_PORT` |

- **Single binary, dual mode** — the GUI relaunches itself with a hidden `--engine` flag and pipes the child's output into the app
- **WinDivert injection** — capture, craft and reinject TCP packets in the Windows network stack via `pydivert`
- **TLS record engineering** — byte-accurate TLS 1.3 templates: ClientHello construction with substituted `server_name` and recalculated padding, round-trip parse validation, ServerHello reconstruction, CCS and Application Data framing
- **Live timestamped console** with a debug toggle that still surfaces real `ERROR:` lines
- **Fail-safe config** — self-healing `config.json`, cloud config and local profiles

> Research, diagnostics and education tool for networks you own or are authorized to test.

`Python 3.10+` `PyQt6` `WinDivert / pydivert` `PyInstaller`

</details>

<summary><b>Huckleberry — record it once, let the AI answer it forever</b></summary>
<br/>

> A **privacy-first browser extension** that records your clicks on any web form, then replays them in a loop while an AI model reads each question and picks the right answer.

| Act | You do | Huckleberry does |
| :--- | :--- | :--- |
| **Record** | Click through one question like a human | Captures every click, keystroke and navigation with a resilient selector per target |
| **Describe** | Point at the question text and the answer element | Compiles a typed step list: `extract` → `ask_ai` → `choose_answer` |
| **Run** | Press Run and walk away | Loops: reads, asks the model, matches the option on screen, submits, logs live |

- **Not a blind click-replayer** — the macro describes the *shape* of the task, the model supplies the *content*
- **API mode and Tab mode** answer engines, stall detection with manual assist, questionnaire memory/context
- **Telegram notifications** for long unattended runs
- **No backend, no telemetry, no account** — macros live in local extension storage, prompts go straight from your browser to your endpoint with your key

`JavaScript` `Manifest V3` `Firefox 115+ / Chrome / Edge / Brave / Opera`

<summary><b>HOMA — hands-on machine assistant</b></summary>
<br/>

> *Most AI assistants can only talk. HOMA acts.*

**Capability surface** — every capability is a tool, every tool comes from an auto-loaded plugin:

| **system** | `disk_usage` `list_dir` `info` `processes` `open` `run_command` |
| **web / mail / files** | `fetch` `search` `download` · `check` `send` · `search` `read` `write` |
| **memory / schedule** | `remember` `recall` `forget` · persistent jobs that survive restarts |
| **utility / desktop** | clipboard, desktop notifications, time, window and app helpers |

**The flagship flow** — open a page, then just handle it: `browser.extract_form` reads every question,
its options **and its real selectors** (it never invents one), the model decides, `browser.fill_form`
writes the answers, then it clicks through and reports what it did.

- **Any model, any provider** — anything OpenAI-compatible: 9Router, OpenAI, OpenRouter, Ollama, LM Studio, vLLM. Change one URL.
- **Guarded by default** — shell and file writes ship disabled; dangerous tools need an explicit *Allow*, backed by a command blocklist and a path guard.
- **Plugin-native** — drop a `.py` file in `plugins/` and the model instantly sees the new tools; no core changes.
- **Streaming REST API** — `/api/command`, `/api/stream` (SSE), `/api/forget`, `/api/tools` behind a bearer token, so a mobile client is just a thin shell.
- **Bilingual and always on** — understands Persian and English with RTL-aware UIs, plus a persistent job store that outlives reboots.

`Python 3.10+` `FastAPI` `Playwright` `APScheduler` `SQLite` `Telegram Bot API` `Docker` `Ruff`

</details>

<details open>
<summary><b>AnonChat — anonymous group chat, engineered for deniability</b></summary>
<br/>

> **Design axiom:** the server should never hold anything worth subpoenaing.

One Telegram bot becomes a **shared anonymous room**. Everyone talks to the bot privately and the bot
relays each message to everyone else — stripped of identity, with no `Forwarded from` header, and
without ever writing message content to disk.

**Two runtimes, one product** (monorepo — pick one, never both on the same token):

| | `node/` — **Core** | `php/` — **Lite** |
| :--- | :--- | :--- |
| Runtime | Node.js ≥ 22.5 | PHP ≥ 8.0 |
| Storage | `node:sqlite` (WAL) | `PDO SQLite` (WAL) |
| Dependencies | **0** — no `npm install` | **0** — no Composer |
| Transport | Long polling *or* webhook | Webhook only |
| Concurrency | Async queue + rate limiter | `curl_multi` parallel fan-out |
| Best for | VPS, Docker, Fly.io, Railway | cPanel / DirectAdmin shared hosting |

**Privacy is not a setting — it is what the code is incapable of doing**

- No text or media column exists in the schema; there is nothing to leak and nothing to hand over.
- Delivery uses `copyMessage`, never `forwardMessage`, so no sender is ever revealed.
- The only persisted data is `(message_id → message_id)` integers, purged after 48h.
- Anti-spam compares in-memory SHA-256 digests and timestamps, not the messages themselves.
- Every webhook request must carry Telegram's `X-Telegram-Bot-Api-Secret-Token`.
- Logs record event names and error codes — never payloads.

**Product surface** — auto-generated aliases (`🦊 Swift Fox #427`) with `/alias` reroll, threaded replies
across copies, edit sync, delete-for-all, full media support, EN/FA `/lang`, a glass-panel `/panel`
admin console, tiered moderators, timed mutes, warnings with auto-ban, one-tap report triage,
word filters, slow mode, flood and duplicate limiting, and an optional forced-subscription gate.

**Performance** — a global send queue respects Telegram's ~30 msg/s ceiling, honours `429 retry_after`
automatically, fans out to ~1,000 recipients in ≈40s, and prunes users who block the bot.

`Node.js 22+` `PHP 8+` `SQLite WAL` `Telegram Bot API` `Docker` `CodeQL CI` `MIT`

</details>
